## Durable engineering directions (map to existing E01–E42; no denominator expansion)

| Workstream | Implementation order / acceptance |
|---|---|
| H01 (E13–E15,E18,E27,E34,E38) — layered context | Implemented candidate in context_packet.py and Council workspace. Validated exact local snapshot; fixed schema, all source holds visible, bounded JSON bytes, summary/review/evidence tiers and explicit omissions. Evidence tier contains IDs, not files or source text. No new attempt, network or grant. Fresh UI inspection per level; pure expansion binds to the same snapshot only. Tests verify digest, drift, false flags, injection-shaped input rejection and byte cap. |
| H02 (E16,E26,E27,E37,E38) — browser harness | API-first. Design a read-only task contract with exact provider/origin, action and time/request limits, deny unknown inputs; isolated ephemeral browser (no logged-in profile), network egress/DNS/redirect/subresource enforcement, no downloads/forms/submissions. Synthetic owned web fixture tests first. Then evaluate pinned Browser Use in a separate Python >=3.11 worker with opt-in model/cost controls and no live commercial activity. Do not confuse browser navigation with authority. |
| H03 (E18,E19,E31,E36,E37) — scoped persistent memory | Extend existing SQLite records with namespace/role, source provenance, expiry, supersession and explicit deletion/retention. Separate declared, observed, modeled, authenticated and revoked records. Benchmark deterministic retrieval before optional embeddings; prohibit memory from becoming instructions or permission. Mem0/OpenViking are reference architectures; evaluate independent local adapters only after dependency/license/telemetry review. |
| H04 (E13,E14,E21,E22,E27,E38) — scientific evaluation | Evidence quality and claim-level uncertainty, distinguish assumptions vs observed data, predefine acceptance and negative controls, independent calculation checks, calibration and sensitivity analysis; benchmark financial/schedule rankings using synthetic fixtures and report failures. No unsupported domain claims or credentials. |
| H05 (E33–E35,E40) — diagram and Matrix | Static, local-only architecture and provenance views, clear decision path, separate status from authority, system fonts, limited nodes/edges, accessible contrast, source/frozen GUI checks. Start with docs/AGENT_CONTEXT_ARCHITECTURE.svg; later add native interactive data views. No external HTML/scripts or remote fonts. |
| H06 (E16,E17,E25–E27,E36–E38) — defensive hardening | Threat model own code; untrusted content never privileged prompts; allowlisted tools, schema validation, least privilege, secret scanning with redaction, dependency/SBOM review, fixture-only prompt-injection and URL boundary tests; evidence-based incident recovery. No scanning or exploitation of external systems. |
| H07 (E03,E04,E15,E17,E31,E38–E42) — harness/release | Explicit contracts, budgets and three-attempt escalation; durable restart/reconciliation; trace and negative-control evaluation, independent QA, atomic verified CI, consolidation and installer/security review before promotion. Model/tool self-reports are not acceptance evidence. |
| H08 (E24–E32,E41,E42) — Operator delivery | Continue native recipient/correspondence review, thread/quote provenance, sandboxed task/deliverable execution, actual acceptance/collection simulations; separate explicit authorization and licensing before real actions. Do not stall commercial roadmap for speculative dependency adoption. |

## Scope and acceptance

H01 is a clean implementation using existing validated Council snapshots (not external LLM generated abstracts). Every packet includes exact source/plan/profile/observation/snapshot pins and zero authority. Summary retains all five criterion states and source hold; detailed levels preserve unresolved evidence and reasons, not arbitrary free text. Reference IDs are not authenticated documents. Maximum encoded bytes 3 KiB/32 KiB/48 KiB, fail closed rather than silently discard blockers. No claim that this is a semantic memory service, a browser runtime, authentication, actual financial return, or independently verified eligibility. Current runtime is trusted single-user local; hashes are integrity checks, not adversarial authentication.

Full transitive dependency vulnerability audits, actual upstream installation, local provider benchmarks and license counsel review remain outstanding. No new runtime packages, paid resources or live network requests for the new feature. No unapproved changes to Nexus Operative. Full private repository clone was blocked by DNS; source/tests/docs published together as one coherent CI candidate, no deliberate failing remote submissions. Eight focused tests and one existing real-runtime workspace integration test; Windows GUI smoke checks all tiers. Formal main acceptance remains 0/42.
