# Scout SAM.gov read-only pilot

Official provider specification: https://open.gsa.gov/api/get-opportunities-public-api/

## Use
Open Scout revenue pathways, choose SAM, select Solicitation or Combined synopsis/solicitation, and click Search SAM (read only). Enter a public title keyword, explicitly consent to one bounded search, then enter your own public SAM API key locally in the masked dialog. Obtain a key from your SAM.gov Account Details page; never send it via chat, commit it, or include it in search keywords. The key is held in process memory for this request, not persisted or exported; this is not a durable encrypted credential vault. The provider requires the key in the HTTPS query string. No actual key or live provider request was used in development or CI.

The desktop uses the previous 14 days through the current UTC date. The adapter permits date windows up to 31 days, one solicitation type, 25 results per page and at most three total requests including retries, with one-second spacing. Provider quotas apply across all calls and accounts; no persistent daily quota enforcement yet. A single transient 5xx may be retried within the cap; 429 stops immediately; 404 reports no-data/not-found ambiguity; other errors fail closed. Fixed HTTPS host api.sam.gov and GET /opportunities/v2/search, default TLS validation, no redirect following, 10-second socket timeout and 2 MiB/page response limit. Total wall time is not a hard deadline. No arbitrary URL, attachment, contact or description retrieval. Consent is checked before and after each request; halt is cooperative and cannot retract an in-flight request.

## Results
Notice IDs, current type, active status, posted date, offset-aware deadline, selected organization and classification metadata, and official notice link are inspected. No implied price or fee from an award amount. Unknown/unzoned deadlines remain blocked. Awards, inactive notices and expired notices are not research candidates. Missing or inconsistent pagination, duplicate IDs, malformed responses and key echoes reject the batch. Report includes retrieval times, page digests and a truncated indicator. Page digests identify received bytes, not independently verified facts. Untrusted response fields are display-only. The provider may require sign-in to view some notices; manual browser links are not proof of access.

Each notice receives its own seven-item evidence checklist. A research candidate is not execution eligible, and all cash exposure remains unknown until supported by evidence. Requirements, eligibility, capability, compensation and approval remain unverified; no lead can authorize bids, outreach, applications, payments or any commitment. Results appear in a native list with per-lead To Do details and explicit official notice opening. The report can be exported locally; no automatic persistence into the OCDS archive (SAM notices are not OCDS compiled releases).

## Acceptance and limitations
R03/E10–E12: mocked network transport, response parsing, request caps, pagination, 429/5xx handling, credential redaction and default-deny consent tests. Live authorized pilot with a real account, persistent quota/rate budgeting, encrypted key storage, source revision/lifecycle reconciliation and source-specific deadline fixtures still needed. R05: lead-specific checklist presentation implemented; durable state and independent evidence verification pending. R06: basic ordering by notice status and deadline, not profitability or verified zero-cost ranking. R07: OS browser link, not embedded WebView2. No additional paid dependency or provider account provisioned.

The generic Governor still denies FETCH_EXTERNAL and all consequential actions. The narrowly scoped SAM policy accepts explicit trusted UI consent for one read-only search only. Do not infer authorization from a source document, agent output, checklist or API key alone.
