# Aegis — local evidence file integrity (R05 candidate)

Scout lead history -> select historical lead -> Review To Do -> select task -> Fingerprint evidence file. Choose an ordinary local file explicitly. Aegis reads bytes (maximum 16 MiB, nonempty), computes SHA-256 and length, and fills a canonical reference. Save selected task separately to persist the reference in the existing context-bound checklist. Check saved fingerprint reselects a file and compares its current bytes with the saved reference; a different file containing identical bytes matches. The check reads the current saved checklist revision before and after the comparison, and revalidates the observation/profile context. No file content, path, or comparison result is persisted or uploaded. The owner may still type ordinary notes. A hash reference is not a signature, authenticated provenance, current contract status or factual proof. All independent verification and transaction-authority flags remain false.

The helper checks the regular-file type and size before opening, uses available no-follow/nonblocking flags, validates file identity and metadata before/after hashing, and checks halt during reads. Explicit UNC/device prefixes and nonregular final path components are rejected. OS filesystem permissions and trusted local selection remain the boundary; mapped drives and parent-directory links are not sandboxed, metadata checks are not a guarantee against adversarial mutation, and a blocking filesystem can still delay the synchronous UI. Never enter credentials or select private documents unnecessarily. No external dependencies, paid services, parser, network access, document execution, or new storage schema. Existing checklist notes remain readable. Digests use the existing LeadStore/ChecklistStore canonical integrity conventions and Python standard-library hashlib (https://docs.python.org/3/library/hashlib.html); no upstream implementation copied.

Next gates: independently authenticated source records, actual evidence content validation and cross-source consistency, documented terms and zero-cash resource feasibility, distinct scoped approvals, durable halt/recovery, live-provider verification. Aegis byte checks do not satisfy legal, eligibility, cost or authorization gates. Ten regression methods plus a Windows GUI smoke fixture that fingerprints, saves, reloads and verifies synthetic bytes.

Windows compatibility note: path-stat and handle-stat timestamps are compared within their own API, not against each other. Cross-API checks compare size and available file identity. Windows filesystems with missing inode IDs fall back to same-API metadata checks, so this is not an adversarial filesystem integrity guarantee. OS permission errors are redacted; Governor denials remain distinct. Twelve regression methods after this correction.
