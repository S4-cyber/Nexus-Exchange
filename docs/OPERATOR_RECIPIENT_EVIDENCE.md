## Local contract
- Resolve an existing scoped RFQ v2 by exact plan and draft IDs. Reenter the exact Atlas supplier declaration; current scenario/profile/observation and declared supplier scope are rechecked before/after preparation and persistence. A stale or changed declaration blocks preparation. History remains explicitly historical.
- Explicit registry scheme, identifier and organization name must agree with the declared supplier. Accept only a bounded lowercase ASCII organization role mailbox (e.g. quotes, procurement, sales) and a declared HTTPS contact source on that exact domain or its www host, without query strings, fragment, credentials or port. No personal mailbox, arbitrary URL retrieval or mailbox-control checks. Matching strings do not prove ownership, authenticity or contact permission.
- Aegis fingerprints an explicitly selected local supporting file only after validating the declaration; no path/raw bytes retained. Preview is read-only. Save requires exact preview recipient ID and literal owner confirmation; changes in the declaration or evidence bytes require preview again. Local notes are not authorization.
- Immutable SQLite operator-recipients.sqlite3 records store minimal declared organization identity, role mailbox, contact-source URL, observation time, file digest/length and exact plan/RFQ/supplier-profile binding. Bounded 10,000 records, up to 100 historical rows per draft, idempotent replay, canonical identity/integrity checks and existing-only read behavior. No contacts created from source data automatically, no email sent, no raw source content, no personal profile credentials. Local plaintext trusted storage, not an encrypted contact vault; a role mailbox may still identify a person in practice. Do not enter private or unnecessary contact details.
- render_correspondence produces a visibly nonbinding local quotation preview addressed to the declared, unverified role mailbox; no mailto, SMTP, Gmail, external browser, dispatch or permission. RuntimeGuard exposes only three fixed local operations: recipient_preview, recipient_save, recipient_history. Existing draft store remains unchanged. All recipient, source, mailbox-control, factual-verification and external-authority flags remain false. Cross-store rechecks are not distributed atomic transactions; historical records can survive a post-commit scope failure.
