# Persistent Scout To Do

Open Scout lead history, select a saved observation and choose Review To Do. Each required check has a state: Pending, Needs follow-up, or Evidence noted. Evidence noted requires a short owner-supplied reference (for example, official notice section 2 or a local document digest). It is an assertion, not independent evidence validation. Do not enter secrets, credentials, personal data or private document content. No link is followed, no document is uploaded, no external action is authorized. A fully noted checklist still cannot enable a bid, application, contract, payment or outreach.

Local SQLite scout-todo.sqlite3 stores only bounded task state, references and UTC timestamps. Each context is tied to the exact source, canonical lead key, retrieval timestamp, canonical observation SHA-256 and optional owner profile content revision. A new observation or changed profile content starts a separate checklist; returning to identical profile content and the same observation restores its previous notes. The native window rechecks the latest archived observation and current profile before reading/saving. Concurrent edits use compare-and-swap revisions; conflicts require reload. Historical notes are retained but not promoted to newer observations. Up to 10,000 contexts, no silent eviction. Plaintext trusted local storage; digests detect accidental corruption, not malicious local edits. Notes are excluded from normal Scout history exports. Cross-database race windows remain possible; an old context cannot grant authority, and the next reload rebinds to current evidence.

Reuses the existing LeadStore and ProfileStore canonical SQLite pattern and shared task definitions. Adds exact-key historical lookup, observation digest projection and native checklist editor. No migration of existing archive rows, external dependencies, provider requests or new paid services. Independent evidence retrieval, verification, expiration/revocation, secure identity/credential storage, actual scoped action approvals and execution remain separate gates. This is a progress-tracking mechanism, not an authorization system.
