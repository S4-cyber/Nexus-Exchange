## Scope and design

`service_handoff.review_scope(review)` is a deterministic consistency pin for a backend-generated Scout review: exact observation/profile context, source hold/blockers, title assessment and full declared requirements assessment, and denied action flags. Evaluation time is deliberately excluded so a current re-evaluation of identical facts can match; it is not a freshness grant or authentication. The Matrix form displays the pin.

`RuntimeGuard.produce_scoped_service_sample(plan_id, context=..., requirements=..., expected_scope=..., raw=..., right_raw=..., confirmed=True)` is a separate owner-thread idle/healthy/explicitly confirmed local entry point. It resolves the saved-plan Council snapshot and freshly reviews the declared requirements via the existing RankingWorkspace. The new helper checks the exact plan context and reviewed scope, no source hold, structural fit, explicit denied authority flags and exact input byte length and SHA-256 for each supplied input. The existing contract parser checks input schema, unique keys, row counts, string safety and the implementation ceilings; the new route also checks actual parsed data cells against the declared (possibly tighter) maximum. All four existing service operations use the same deterministic producer and mechanical reparse QA. The runtime independently rechecks the plan contract and then re-evaluates the Scout scope before returning the transient sample and pin; halt or changed context withholds output. No arbitrary callback, file IO for supplied sample bytes, new ledger, registration, transmission, external authority, automatic selection, payment or actual customer acceptance. The existing archive/profile reads are not adversarially atomic. The pin and caller's explicit local confirmation do not prove ownership/data-use consent or actual commercial facts. This increment is callable backend functionality; a native explicit sample-handoff/file-selection control is still required. Existing local preview/export/registration and Governor rules are unchanged.
